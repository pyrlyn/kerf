### T18. Shared screen logic for every host

The logic behind the IDE screens (mockups: Figma file `gNfemQ9NFKFNT2fifxb6sm`, pages "Kerf IDE · macOS dark" and "UI Kit"), written once in Rust and kept apart from the views (on the creator's word, 2026-11-08). Each area is a crate with no UI dependency: plain state snapshots, actions, and change notifications, exposed through `kerf-ffi` so the macOS (AppKit), Linux (GTK 4) and Windows (WinUI 3, `roadmap.md`) hosts draw it without their own copy of the logic. Views come in later tasks.

Shared rules for the subtasks: one crate per area under `crates/`; every list, queue and buffer fed by a process, a plugin or a repository has a hard cap; the C ABI lives in its own `crates/kerf-ffi/src/<area>.rs` with the header regenerated by cbindgen; headless tests cover the model and the C ABI.

#### T18.1. Workspace and trust model

`kerf-workspace`: recent folders (stored outside the repository), opening a folder, the Workspace Trust prompt's contents (language servers, debug adapters, tasks and project plugins that would start, with their commands verbatim), restricted mode, and revoking trust, on top of `kerf-core`'s trust store. Done when tests open trusted, untrusted and remembered folders, build the prompt from manifests, and see revoke report what to stop; the same through `kerf_workspace_*`.

#### T18.2. Navigator and Open Quickly

`kerf-navigator`: a lazy, capped file tree that honours ignore files (expand, collapse, select, filter), and Open Quickly ranking files and `kerf-semantic` symbols by fuzzy match. Done when tests drive the tree over a temporary project and rank queries; the same through `kerf_navigator_*`.

#### T18.3. Terminal sessions

`kerf-terminal`: terminals the core owns: a PTY per tab (ConPTY on Windows), started only after the trust check, a VT screen model, input, resize, close, a 4 MiB output cap, and tabs a plugin opened through `ide.terminal` marked as such. Done when tests run a shell command through the PTY on macOS and Linux, read the screen back, hit the cap, and refuse a spawn in an untrusted folder; the same through `kerf_terminal_*`.

#### T18.4. Plugins and permissions model

`kerf-plugin-manager`: the plugins list (enabled, disabled for the session after 3 failures, digest mismatch against `kerf-plugins.lock`, project plugins waiting for a per-repository enable) and the permission prompt (grant lines verbatim, digest, wider capabilities asking again), on top of `kerf-plugin` and `kerf-plugin-lock`. Done when tests cover each state and each grant decision; the same through `kerf_plugins_*`.

#### T18.5. Source control model

`kerf-scm`: repository status (staged, unstaged, untracked; capped), per-file diff hunks, stage, unstage, and commit with a message. No push. Done when tests run against temporary git repositories; the same through `kerf_scm_*`.

### T17. Linux host on GTK 4

The Linux host for the UI shell (from `roadmap.md`, approved with T12's native direction): a GTK 4 window over T12's C ABI with the Slint editor surface from T16, looking like GNOME Text Editor. Done when the Linux app opens a file, shows it in the Slint-drawn view, takes typing, selection, undo and redo through `kerf-core`, takes input-method text through GTK, draws a GTK-style caret, and headless tests of that path run in CI on `ubuntu-latest`.

The creator's choices (2026-10-20): the host is Rust on gtk4-rs calling `kerf-ffi`'s C functions; the look is GNOME Text Editor's on plain GTK 4 (no libadwaita).

Split when claimed (500-line task cap) into three stacked pull requests. Research for all three is in `research.md` §7, "Linux host (T17)". Locally the Linux tests run in a Lima VM from `template:ubuntu-24.04` (GTK 4.14, as on the CI runner).

#### T17.2. Editor view widget

`EditorView`, a `GtkWidget` subclass: `kerf_view_*` draws into a `GdkMemoryTexture` shown in the widget's snapshot; keys through a key controller with a `GtkIMMulticontext` (commits as typed, no inline preedit); GTK's caret over the frame with GtkTextView's blink, hidden over a selection; the look re-applied on theme and font changes. Done when tests under Xvfb type through the input method and keys, select, undo, redo and read the frame's pixels and the caret back.

#### T17.3. Linux app window

`kerf-gtk` binary: a `GtkApplication` that opens files from the command line and an Open dialog, one window per file with a header bar (Open, main menu with Undo, Redo, Select All) and GNOME's shortcuts. Done when a test builds the window for an opened file and drives its actions.

### T15. Mobile plugin backend

An interpreter backend (wasm3, WAMR or a maintained pure-Rust interpreter, chosen against each other) behind the same host API, for iOS and Android where wasmtime cannot JIT. Depends on T6. Done when the T6 plugin tests pass unchanged against the interpreter backend on the desktop host, and the choice and its limits are recorded in `research.md`.

Plan (approved by the creator: wasmtime's Pulley interpreter through a `pulley` feature of the shared host):

1. pyrlyn/crates T20.6 (pyrlyn/crates#107): feature `pulley` on `wasm-plugin-host` and `plugwright-extism` hands extism a `wasmtime::Config` targeting Pulley; their suites pass with it on.
2. Kerf: bump the `wasm-plugin-host` git pin to the merged commit; `kerf-plugin` feature `interpreter` forwards to `wasm-plugin-host/pulley`, and iOS and Android targets turn it on.
3. CI runs `cargo test -p kerf-plugin --features interpreter` beside the default run; `crates/kerf-plugin/tests/plugins.rs` stays unchanged.
4. `research.md` §8: candidates with primary sources, the choice and its limits; `toolchain.md` row.
